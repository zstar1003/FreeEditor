# OSS 同步安全边界

同步采取保守合并：本地缺失不等于用户删除，另一设备可能刚创建该文档或文件夹。旧版 `deletedItems` 也是从缺失推导，不能作为可靠删除记录。因此当前同步不会传播删除，也不会依据旧删除列表删除本地文档。本地删除的内容可能在下一次同步重新出现。

读取远程文章失败、JSON 无法解析、索引缺少数组或文章内容不是字符串时，同步将报错且不上传合并结果，避免用不完整的下载结果覆盖索引。这不会自动修复旧版已经丢失的索引记录。

## 仍需注意

- 同步不是事务备份。当前上传仍先写索引、再覆盖固定文章对象；上传部分失败可能产生索引与文章不一致。
- 不支持多设备/多窗口并发提交的冲突检测。请避免同时同步，操作前保留独立导出备份。
- 同步过程中继续编辑时，界面应用返回快照也可能覆盖新的本地修改；等待同步结束再编辑。
- “恢复孤立文章”会重建并写入云端索引，不是只读预览，不应在唯一备份上直接试用。
- 本修复不包含历史数据恢复、版本化对象、条件提交、显式删除协议或完整离线冲突合并。

验证：`node --test tests/oss-sync.test.cjs` 使用合成文档和内存 OSS，不访问真实桶。前端构建使用 `npm run build`。这不是阿里云或打包 Electron 客户端的端到端测试。
